# 母婴打卡小程序 - 数据存储方案

## 1. 总体架构

### 1.1 数据存储架构

```
┌─────────────────────┐     ┌─────────────────────┐     ┌─────────────────────┐
│      微信小程序      │     │      云函数         │     │      云数据库       │
│      前端应用       │◄───►│      服务层         │◄───►│                     │
└─────────────────────┘     └─────────────────────┘     └─────────────────────┘
                                      ▲                        ▲
                                      │                        │
                                      ▼                        ▼
                              ┌─────────────────────┐     ┌─────────────────────┐
                              │      云存储         │     │      云调用         │
                              │ (图片、音频等媒体)   │     │ (第三方API集成)     │
                              └─────────────────────┘     └─────────────────────┘
```

### 1.2 数据流程

1. **数据写入流程**：
   - 用户在小程序前端提交数据
   - 前端调用云函数或直接操作云数据库
   - 数据经过验证和处理后存入云数据库

2. **数据读取流程**：
   - 前端发送数据请求
   - 通过云函数查询或直接查询云数据库
   - 数据返回给前端进行展示

## 2. 数据库设计

### 2.1 数据库表结构

#### 2.1.1 用户表（users）

| 字段名 | 数据类型 | 描述 | 索引 | 必填 |
|-------|---------|------|------|------|
| _id | string | 微信用户唯一标识 | 是 | 是 |
| openid | string | 微信用户openid | 是 | 是 |
| nickName | string | 用户昵称 | 否 | 是 |
| avatarUrl | string | 用户头像URL | 否 | 是 |
| gender | number | 性别（0:未知, 1:男, 2:女） | 否 | 否 |
| country | string | 国家 | 否 | 否 |
| province | string | 省份 | 否 | 否 |
| city | string | 城市 | 否 | 否 |
| language | string | 语言 | 否 | 否 |
| createdAt | timestamp | 注册时间 | 否 | 是 |
| updatedAt | timestamp | 更新时间 | 否 | 是 |


### 2.2 索引设计

| 表名 | 索引字段 | 索引类型 | 用途 |
|-----|---------|---------|------|
| users | openid | 唯一索引 | 用户登录和身份验证 |
| users | _id | 唯一索引 | 用户数据查询 |
| tasks | userId | 普通索引 | 查询用户的所有事项 |
| tasks | userId, status | 复合索引 | 查询用户的有效事项 |
| tasks | userId, startDate | 复合索引 | 按日期范围查询事项 |
| checkRecords | userId, checkDate | 复合索引 | 查询用户指定日期的打卡记录 |
| checkRecords | taskId | 普通索引 | 查询事项的所有打卡记录 |
| checkRecords | userId, taskId, checkDate | 复合索引 | 查询用户某事项在特定日期的打卡记录 |
| recommendedTasks | type | 普通索引 | 按类型查询推荐事项 |
| recommendedTasks | tags | 数组索引 | 按标签查询推荐事项 |

### 2.3 安全规则设计

#### 2.3.1 users 集合安全规则

```javascript
{
  "read": "auth != null && resource.data._id == auth.uid",
  "write": "auth != null && resource.data._id == auth.uid"
}
```

#### 2.3.2 tasks 集合安全规则

```javascript
{
  "read": "auth != null && resource.data.userId == auth.uid",
  "write": "auth != null && (resource.data.userId == auth.uid || !resource.exists)",
  "update": "auth != null && resource.data.userId == auth.uid"
}
```

#### 2.3.3 checkRecords 集合安全规则

```javascript
{
  "read": "auth != null && resource.data.userId == auth.uid",
  "write": "auth != null && (resource.data.userId == auth.uid || !resource.exists)",
  "update": "auth != null && resource.data.userId == auth.uid"
}
```

#### 2.3.4 recommendedTasks 集合安全规则

```javascript
{
  "read": true,
  "write": false
}
```

## 4. 数据同步策略

### 4.1 实时同步

- **使用云数据库的实时监听功能**：监听用户相关的数据变化
- **场景**：多端登录时的数据同步

### 4.2 离线数据处理

- **本地缓存**：关键数据缓存到本地
- **同步机制**：网络恢复后自动同步本地操作

### 4.3 数据一致性保障

- **事务处理**：关键操作使用事务保证原子性
- **冲突解决**：基于时间戳的冲突检测和解决

## 5. 性能优化

### 5.1 数据库性能优化

- **索引优化**：合理设计索引加速查询
- **查询优化**：避免全表扫描，使用投影减少数据传输
- **聚合查询**：使用聚合操作减少网络请求次数

### 5.2 云函数性能优化

- **冷启动优化**：合理设置函数超时时间
- **内存配置**：根据函数复杂度设置合适的内存
- **并行处理**：适当使用并行处理提高效率

### 5.3 缓存策略

- **小程序缓存**：使用小程序本地存储缓存不常变化的数据
- **云函数缓存**：使用内存缓存频繁访问的数据

## 6. 数据安全

### 6.1 数据加密

- **敏感数据**：敏感数据加密存储
- **传输加密**：使用HTTPS保证传输安全

### 6.2 访问控制

- **基于角色的权限控制**：严格限制数据访问权限
- **API鉴权**：所有API调用需要身份验证

### 6.3 数据备份与恢复

- **自动备份**：定期自动备份数据库
- **恢复机制**：建立数据恢复流程和机制

## 7. 扩展性考虑

### 7.1 数据模型扩展性

- **文档型数据库优势**：灵活的数据模型便于扩展
- **版本控制**：通过字段标记数据结构版本

### 7.2 未来功能扩展

- **数据分析**：预留数据分析所需的字段和索引
- **社交功能**：为未来可能的社交功能预留数据模型扩展点
